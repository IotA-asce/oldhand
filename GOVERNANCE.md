# Governance

Lore is maintained as an open-source, local-first project. This document makes
decision-making visible while the project is still small.

## Roles

- **Maintainers** steward releases, security responses, the roadmap, and the
  repository's technical direction.
- **Contributors** improve code, documentation, tests, examples, and
  discussions through issues and pull requests.
- **Users** provide feedback based on real archives and workflows; they do not
  need to contribute code to influence priorities.

The initial maintainer and succession contact must be named in this file before
the project is publicly launched: **[MAINTAINER / SUCCESSION CONTACT TO BE
ADDED BEFORE PUBLIC LAUNCH]**.

## Decisions

Maintainers make final decisions after considering evidence, user impact,
maintainability, compatibility, security, and the project's local-first
principles. Significant changes should be proposed publicly in an issue,
discussion, or pull request whenever security or privacy does not require a
private process.

For changes that affect archive format, retrieval guarantees, data safety,
privacy, or public APIs, maintainers should document the rationale, migration
path, and verification plan.

## Contributions and reviews

Contributions follow [CONTRIBUTING.md](CONTRIBUTING.md). At least one maintainer
approval is required before merging. Maintainers should avoid approving their
own substantial change when another active maintainer is available.

## Releases

Maintainers publish releases with notes, version tags, validation evidence, and
any migration instructions. Security fixes follow [SECURITY.md](SECURITY.md).

## Changes to this policy

Maintainers may amend this document through a public pull request. Material
changes should explain the reason and allow community feedback before taking
effect, except where an urgent security or safety concern requires immediate
action.
