# Documentation Policy

Documentation describes current system truth for humans and agents.

Use documentation for:
- architecture and subsystem explanations;
- feature behavior;
- APIs and contracts;
- operational workflows;
- runbooks;
- known limitations;
- safe modification guidance.

Do not use durable memory as a substitute for current documentation.

When behavior changes, update the smallest documentation surface that would otherwise
become misleading.

Documentation answers "how does it work now?"
Memory answers "what should future work remember about why, constraints, traps, and
history?"
