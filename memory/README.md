# Memory

Canonical durable project knowledge lives here as Markdown.

Suggested structure:

```text
memory/
├── MEMORY_INDEX.md
├── topics/
├── decisions/
├── constraints/
├── fixes/
├── investigations/
├── migrations/
├── incidents/
├── lessons/
├── features/
└── reference/
```

`MEMORY_INDEX.md` is generated by `lore rebuild`. Do not edit it by hand.

The three records shipped here are examples of the genre, not policy: a trap
that cost a day, a constraint that breaks production silently, and a pointer
to something in an unexpected place. Each is findable from a question that
shares almost none of its wording, which is the property to aim for. See
`WRITING_RECORDS.md`. Delete them once you have records of your own.

A workspace may hold one of these archives per repository. Each one gets its own
generated `MEMORY_INDEX.md`; a single database at the workspace root indexes
them all.

The SQLite database used for search is derived and should normally be ignored by Git.
